# Time-VLM 复现 —— w/o-VLM 消融异常定位报告

> 日期：2026-10-12。方法：4 路并行分析（代码追踪 / 论文对照 / 已训 checkpoint 前向探查 / 机制理论），全部 forward-only，未运行任何训练。
> 结论对象：为什么 full 与 w/o-VLM 指标几乎相同（h96: 0.3637 vs 0.3636；h720 反而 0.4524 vs 0.4399）。

---

## 1. TL;DR

**"VLM 分支贡献≈0"是真实且结构性的，根因在输入端，不是 gate 或训练问题。** 四重机制叠加：

1. **文本 prompt 被 77 字符截断**（[model.py:363](src/TimeVLM/model.py#L363)），模板句本身 162 字符 → 所有样本送入 CLIP 的文本完全相同（实测 2785 个测试样本 text 嵌入成对余弦 = 1.000000）。
2. **视觉图像生成器从未被训练**：`_normalize_images` 的 uint8 强转切断 autograd（[model.py:407](src/TimeVLM/model.py#L407)）→ 训练后 checkpoint 中该模块 11667 个参数与 seed-2024 随机初始化**逐位相同**（rel diff = 0.00000000），CLIP 看到的永远是随机卷积的随机扭曲图。
3. **冻结 CLIP 对 56px 时序渲染图嵌入退化**：全测试集图像嵌入两两余弦均值 0.9953，接近恒定向量。
4. **跨变量结构盲区**：cross-attention 的 K/V 是把同一个 [B,d] 向量 expand 到 7 个通道（[model.py:268](src/TimeVLM/model.py#L268)），VLM 分支对 7 个变量输出完全相同（实测 std = 0.0），只能提供公共偏移。

**近因（gate 坍塌）**：软门学成 h96 w_multimodal = 0.00077 / h720 = 0.0161，且这是**训练出的正确决策**——实测强制 w_v=1 反而使 MSE 恶化 30–44%（h720 0.454→0.652），强制 w_v=0 则 MSE 与最终输出 5 位小数相同。恒等残差 `+ memory_features`（[model.py:297](src/TimeVLM/model.py#L297)）是无代价绕过路径。

**h720 上 w/o-VLM 好 2.8% 的解释**：不是"去掉 VLM 信息"带来的，而是 wovlm 独立重训练出更优的 memory 分支（其 memory 分支单独 MSE 0.489 vs full 的 0.501，差值 0.012 ≈ 头条差距 0.0125）。

## 3. 与论文的关系（重要：这不否定复现）

- 论文自己的唯一模态消融（arXiv v2 **Table 6，Weather**）：w/o VAL（视觉）+9.0% MSE、w/o TAL（文本）仅 +2.1%、w/o RAL（时序记忆）+35.6%；且 **w/o VAL 在 h720 反而比 full 好 2.5%**（0.309 vs 0.317）——与我们 ETTh1 上"h96 无差异、h720 略优"的趋势定性一致。
- 论文**未报告任何 ETTh1 上的消融数字**；其声称的 ETTh1 full-shot 增益本就很薄：对 PatchTST 每 horizon 仅 +1.3%–3.9%，对 Time-LLM 平均 +0.7%。
- **77 字符截断 bug 自论文时期提交（2025-05-26, b488910）起就存在**——论文自己的运行中文本模态同样是常数向量。
- 论文 slide 的 Future Work 自列 *"Visual distillation — visual encoder may be redundant compared to time series"*。
- 因此：**full h96 0.3637 ≈ 论文 0.361 且 VLM≈0，最可能解释是论文 headline 数字主要由时序/记忆骨干（RAL）贡献，VLM 增益在其叙事中就被高估**。我们的 Tier 1 复现结论不受影响；消融判定的正确表述应为"仓库实现中 VLM 分支不携带可用信息"，而非"VLM 概念无效"。

## 4. 修复验证实验清单（按信息量/成本排序，均单卡 5090 可跑）

| 编号 | 实验 | 验证的根因 | 预估耗时 |
|---|---|---|---|
| **E1** | 修 uint8 断链（图像保持 [0,1] float 或 [0,255] float + CLIPProcessor rescale），重跑 h96 full + w/o-VLM | 视觉梯度断链（根因 2） | ~15 min |
| **E2** | `finetune_vlm=True`（解冻 CLIP，lr 建议 1e-5）重跑 h96 | 冻结 CLIP OOD 退化（根因 3） | ~30-40 min |
| E3 | 分模态消融（仅 w_out_visual / 仅 w_out_text），在 E1/E2 出现增益后跑 | 视觉 vs 文本归因 | ~20 min |
| E4 | `vlm_type=custom`（可训练 ViT+BERT） | 绕开冻结 CLIP | ~40 min（含权重下载） |
| E5 | 逐变量 VLM 嵌入（去掉 expand 共享 K/V，或每变量分别编码） | 跨变量盲区（根因 4） | 需改代码，~30 min |
| E8 | 信息量 prompt（逐变量统计，修 77 字符截断） | 文本截断（根因 1） | ~15 min |

> E1/E2 若能使 full > w/o-VLM 且 gate w1 上升，即确认根因链；届时结论可写为"仓库实现的三个具体缺陷（uint8 断链、OOD 冻结编码器、跨变量盲区）导致 VLM 分支未生效"。
> 修复实验涉及改 src/TimeVLM/model.py，建议在 git 分支上进行，跑完即还原。

## 5. E1 实验记录（2026-10-12 已执行）

**修复内容**（分支 `ablation-e1-uint8fix`，commit `ff72cec`，跑完已还原 main）：
- `_normalize_images`：去掉 uint8 强转，保留 float32 [0,1]（[model.py](src/TimeVLM/model.py)）
- `_process_clip_inputs`：绕开 CLIPProcessor 的图像预处理（其内部 numpy/PIL 往返同样切断计算图），改为纯 torch 的 bicubic 缩放 56→224 + mean/std 归一化（数学上等价）

**修复生效验证**：
- 修复前：图像生成器 0/6 参数收到梯度（且 checkpoint 与随机初始化逐位相同）
- 修复后：6/6 参数收到梯度（grad L1=5652.8）；E1 训练后权重确实移动（conv2d_1.bias 相对初始化 mean relΔ=2.90，max|Δ|≈0.025）

**E1 训练结果（h96，其余配置与主实验完全一致）**：

| 配置 | MSE | gate w_multimodal |
|---|---|---|
| E1 full（梯度修复） | 0.363682 | 0.000779（max 0.00101） |
| E1 w/o-VLM（梯度修复+置零） | 0.363648 | — |
| 原版 full | 0.363693 | 0.000766 |
| 原版 w/o-VLM | 0.363648 | — |

**E1 结论：梯度断链不是唯一根因。** 图像生成器可训练后，full 与 w/o-VLM 仍并列（差 0.000034），gate 仍把 VLM 分支压到 0.00078——模型依然学不到有用的视觉信号。瓶颈确在下游：冻结的 OOD CLIP 编码器（对时序渲染图嵌入近乎恒定）+ 跨变量结构盲区 + 恒定文本 prompt。

**旁证**：E1 w/o-VLM 与原版 w/o-VLM 的 MSE **逐位相同**（0.3636479079723358）——置零嵌入切断了视觉梯度路径，修复对 wovlm 本就无影响，与理论完全自洽。

**下一步建议**：E2（`finetune_vlm=True` 解冻 CLIP，lr 1e-5）——若解冻后仍无增益，则"冻结 CLIP OOD 退化"假设被推翻，问题集中在 E5（跨变量结构）与 E8（文本截断）；若出现增益，则视觉编码器冻结是主要瓶颈。

## 6. 官方代码对比结论（2026-10-12）

**问题**：我们的复现是否因代码缺漏导致 VLM≈0？官方 GitHub 代码是否不同？

**结论：复现与官方代码逐字节一致，不存在任何缺漏；VLM≈0 是官方代码本身的实现状态。**

证据链：

1. **官方仓库最新提交 = 我们训练的提交**。`CityMind-Lab/ICML25-TimeVLM`（README badge 自证的官方仓库）HEAD 为 `796e6ec`，经 GitHub API 校验其 tree SHA `3bb0b250afdb6c87b024e307fe25403b6a6c1ef8` 与本地逐字节相同，父提交 `863a934` 一致。本地仓库包含官方全部 11 个提交的完整历史（`b488910` 2025-05-26 论文时期 → `796e6ec` 2025-06-06）。

2. **四个"VLM 失效"设计点在论文时期代码中全部存在**（`git show b488910` 逐字核对）：

   | 设计点 | b488910（论文时期） | 当前 796e6ec |
   |---|---|---|
   | 77 字符 prompt 截断 | :334 | :363（逐字相同） |
   | uint8 强转切断梯度 | :378 | :407（逐字相同） |
   | 跨变量 expand 盲区 | :240 | :268（逐字相同） |
   | 恒等残差 + memory_features | :269 | :297（逐字相同） |

3. **发表后官方仓库的全部改动都在时序分支**，无一触及 VLM 融合语义：PatchMemoryBank 环形缓冲 bug 修复（a4be352）、新增 use_mem_gate/memory_fusion_gate、CLIP 本地缓存加载 try/except、prompt_bank 内容 +1 行（且被 77 字符截断中和，内容根本进不了编码器）、图像生成器重写（3ch+变量平均+ReLU → 4ch FFT+无平均+tanh；但两种版本都被 uint8 断链中和，生成器从未被训练过）。

4. **作者亲口确认**（官方 issue #9/#11，2025-08）：截断是 **"intentional"**，且作者自述*测试过保留完整文本上下文（拆分 prompt、融合嵌入）"saw no performance improvement"*——即论文作者自己的实验同样发现文本分支无增益。

**最终判断**：论文的 headline 数字由时序/记忆骨干（RAL）贡献（论文自身 Weather 消融：w/o RAL +35.6%，w/o TAL 仅 +2.1%）；VLM 分支在官方实现中自始至终贡献≈0。我们的复现（Tier 1 一致）忠实地反映了官方代码的真实行为——**"VLM 增益"存在于论文叙事中，而非代码中**。向导师汇报时可据此表述：复现无缺漏；官方实现存在 4 个使 VLM 分支失效的设计缺陷（论文时期即存在）；若要展示 VLM 的真实价值，需在修复后的代码上验证（E2/E5/E8）。
