**关键代码事实（静态分析结论）：**

1. **随机种子固定为 `2024`**：`run.py:27-30` 硬编码 `fix_seed=2024`，作用于 `random/torch/numpy`；但**未设置 `torch.cuda.manual_seed`**、无 `cudnn.deterministic`。`--itr` 仅重复训练不改变种子。
2. **VLM 预训练权重来源（HuggingFace）**：
   - CLIP（默认）：`openai/clip-vit-base-patch32`（hidden=512，ViT-B/32 ~151M）
   - BLIP2：`Salesforce/blip2-opt-2.7b`（hidden=2560，2.7B —— 4GB 不可行）
   - ViLT：`dandelin/vilt-b32-finetuned-coco`（hidden=768）
   - custom：`google/vit-base-patch16-224` + `bert-base-uncased`（768）
3. **前向 I/O**：`Model.forward(x_enc, ...)`，输入 `[B, seq_len=512, 7]` → 输出 `[B, pred_len, 7]`（ETTh1 7 通道）。
4. **`head_nf = d_model × 64`**（seq_len=512、patch_len=16、stride=8 → 64 个 patch）。
5. **重要坑位**：
   - `--gpu` 默认 **1**（`run.py:122`），单卡 RTX3050/5090 必须传 `--gpu 0`，否则 `cuda:1` 越界报错。
   - `e_layers/d_layers/n_heads/d_ff/factor` 对 TimeVLM 是**死参数**（时序骨干是 patch embedding + 记忆注意力 + 交叉注意力，非堆叠 Transformer）。
   - 消融开关 `w_out_visual/w_out_text/use_cross_attention` 是**死代码**（未接入 forward），"w/o VLM" 消融需补丁接入（已提供 `patch_w_out_vlm.py`）。
   - 本仓库 PatchTST 是**简化版**（无 individual head / decomposition / subtract_last），其指标不会与论文原 PatchTST 完全一致，应视为"本仓库自有基线"。
   - `run.py:60` 的 `help='prior anomaly ratio (%)'` 含 `%` 字符，导致 `run.py --help` 抛 `ValueError`（argparse 用 `%` 格式化帮助文本）。**仅影响 --help 显示，不影响正常训练**。
6. **硬编码路径**：数据 `./dataset/ETTh1.csv`（脚本覆写 run.py 默认 `./data/ETT/`）；prompt bank `./dataset/prompt_bank/ETT.txt`；checkpoint `./checkpoints/{setting}/checkpoint.pth`；结果 `./results/{setting}/`、`result_long_term_forecast.txt`。

## 4. 本地单样本前向测试结果（全部 PASS，无 OOM）

实测环境：RTX3050 Laptop 4GB（4,294.5 MiB），torch 2.2.2+cu118，CUDA 11.8，CLIP 权重已缓存。

| 模型 | 配置 | 总参数 | 可训练参数 | 输入 → 输出 | 维度匹配 | 峰值显存 | 结果 |
|---|---|---|---|---|---|---|---|
| TimeVLM | h96 (d_model=32, mem_gate=False) | 151.6M | 0.36M | [1,512,7]→[1,96,7] | ✅ | 622.5 MB | **PASS** |
| TimeVLM | h720 (d_model=256, mem_gate=True) | 170.7M | 19.45M | [1,512,7]→[1,720,7] | ✅ | 708.0 MB | **PASS** |
| PatchTST | h96 | 1.32M | — | [1,512,7]→[1,96,7] | ✅ | 153.6 MB | **PASS** |
| PatchTST | h720 | 6.43M | — | [1,512,7]→[1,720,7] | ✅ | 174.2 MB | **PASS** |

**结论：**
- 模型导入、实例化、单样本前向推理全部成功，**无 OOM、无报错**；输出维度与论文描述完全一致（`[B, seq_len, n_vars] → [B, pred_len, n_vars]`），输出为有限值（`output_finite=True`）。
- CLIP 冻结生效：TimeVLM h720 总参数 170.7M，可训练仅 **19.45M**（时序/融合头），与静态估算一致；CLIP ViT-B/32（~151M）全部冻结（VLM 打印 "Learnable model parameters: 0"）。
- 训练态前向（`torch.enable_grad()`，**仍无 backward**）峰值 708.6 MB，与推理态几乎一致（因 CLIP 冻结不保存激活）。
- **显存缩放极平缓**：batch 1→2→4→8 仅 705→713→720→749 MB（~5.5 MB/batch），显存由 CLIP 冻结权重（~680MB）主导。

**过程中发现并解决的 3 个依赖问题**（详见 §2）：① `pytorch_wavelets` 未列入 requirements.txt；② 需 `setuptools<81`（pkg_resources）；③ `reformer-pytorch` 未固定 torch 依赖会升级 torch。

## 6. RTX5090 显存评估报告

### 6.1 静态参数/显存估算（d_model=256, horizon=720，最大配置）

| 组件 | 参数量 | FP32 权重 |
|---|---|---|
| CLIP ViT-B/32（冻结，finetune_vlm=False） | ~151M | ~604 MB |
| TimeVLM 时序/融合头（可训练） | ~19.4M | ~78 MB |
| **训练额外**：梯度 | 19.4M | 78 MB |
| **训练额外**：Adam 优化器状态（2 矩） | 19.4M×2 | 155 MB |

**训练时"底板"占用 ≈ 604 + 78 + 78 + 155 ≈ 915 MB**（与 batch 无关），激活随 batch 线性增长。

### 6.2 实测数据（本机 RTX3050 4GB，前向-only）

TimeVLM h720（最大配置）前向峰值显存随 batch 的实测缩放：

| batch | 1 | 2 | 4 | 8 |
|---|---|---|---|---|
| 峰值显存 | 705 MB | 713 MB | 720 MB | 749 MB |

→ **每增加 1 batch 仅 +~5.5 MB**（CLIP 冻结、激活极小）。据此外推 batch=32 前向 ≈ 875 MB。

### 6.3 结论与建议（RTX5090 32GB）

- **训练时总占用估算**（TimeVLM h720，batch=32）：权重 683MB（CLIP 冻结）+ Adam 优化器状态 156MB（19.45M 可训练×2 矩）+ 梯度 78MB + 激活 ~100MB ≈ **~1.0 GB**。远小于 32GB。
- **论文默认 batch_size=32 完全安全**（预计峰值 ≤ 1.5GB）。可放心上探 64 甚至 128。
- FP16（AMP，仓库已默认 `--use_amp`）：可再降 ~40% 显存，且 5090 有 FP16 加速。
- **梯度检查点：不需要**。TimeVLM 时序分支无原生支持，且 CLIP 已冻结（不存激活），检查点收益可忽略。
- **梯度累积：不需要**。batch=32 仅占 ~1GB，无需累积。
- OOM 风险点（仅警告）：`head_nf = d_model×64`，d_model=512 时 `memory_head`/`temporal_head` 各 ~23.6M 参数；**d_model 不要超过论文默认**（ETTh1 最大 256），否则线性层与优化器状态爆增。BLIP2（2.7B）不可用，务必保持 `vlm_type=clip`。
- 探测脚本：`repro/memory_probe.py`（本地 3050 必须 `--forward-only`；5090 上去掉该开关可测前向+反向）。

### 6.3 显存探测脚本

`repro/memory_probe.py`：扫描 batch × FP16 × 梯度检查点。本地 3050 必须 `--forward-only`（不 backward，遵守"禁止训练"红线）；5090 上去掉该开关做单步前向+反向显存探测。

## 8. 验收标准（MSE/MAE 阈值，判定复现成功/失败）

论文逐 horizon 精确值（已从官方 PDF `586_Time_VLM_Exploring_Multimo.pdf` 附录 Table 16 提取，ETTh1）：

| Horizon | Time-VLM MSE | Time-VLM MAE | PatchTST MSE | PatchTST MAE |
|---|---|---|---|---|
| **96** | **0.361** | **0.386** | 0.370 | 0.399 |
| 192 | 0.397 | 0.415 | 0.413 | 0.421 |
| 336 | 0.420 | 0.421 | 0.422 | 0.436 |
| **720** | **0.441** | **0.458** | 0.447 | 0.466 |
| Avg | 0.405 | 0.420 | 0.413 | 0.430 |

> 已核对：Avg 行与主文 Table 2 聚合完全一致（Time-VLM 0.405/0.420、PatchTST 0.413/0.430）。

**判定规则（按优先级）：**

1. **成功（Tier 1）**：TimeVLM 的 h96/h720 MSE 相对论文对应值的**相对误差 ≤ 5%**（MAE ≤ 5%）。
2. **基本成功（Tier 2）**：相对误差 ≤ 10%，且满足单调性（h96 MSE < h720 MSE）。
3. **失败**：相对误差 > 10%，或 TimeVLM 未跑赢本仓库 PatchTST 基线（消融方向反了），或出现 NaN/Inf。
4. **消融验证**：exp③(w/o VLM) 的 MSE 应 **≥** exp②(full) 的 MSE（去掉 VLM 应不优于完整模型，否则说明 VLM 分支未起作用或补丁有误）。

**两个已知的指标偏差来源（复现时需知晓）：**
- 论文数据集统计表写 ETTh1 划分为 **(8545, 2881, 2881)**，而仓库代码为 12/4/4 月即 **(8640, 2880, 2880)** 原始行，存在细微不一致，可能导致小幅指标差异。
- 本仓库 PatchTST 是**简化版**，其指标不会与论文原 PatchTST 完全一致，应视为"仓库自有基线"。

> 说明：指标在 StandardScaler 归一化空间计算（脚本未传 `--inverse`），与论文基准一致，可直接对比。

## 9. 终止策略（指标偏离过大时自动停止）

仓库内置 `EarlyStopping(patience=5)`：验证 MSE 连续 5 个 epoch 不下降即停（已天然限制最坏情况 ≤15 epochs）。但缺少"发散/异常"检测，补充策略：

1. **首 epoch 发散检测**：若第 1 个 epoch 的验证 MSE > **2.0**（ETTh1 归一化空间，正常应 < 1.0，论文 ~0.4），说明配置/数据/模型有误，立即终止，不要跑完剩余 epoch。
2. **NaN/Inf 检测**：仓库 `utils/tools.py:378 check_numerical_stability()` 已实现但未被调用；若日志出现 NaN/Inf loss，立即终止（长 horizon 720 无梯度裁剪，存在该风险）。
3. **早停已生效**：patience=5 下，多数实验会在 10–15 epoch 内收敛，无需跑满。

**落地方式**：`run_5090.sh` 运行后用 `grep` 检查日志中的 `Vali Loss` 首值；若超阈值则 `kill` 进程并输出诊断（建议人工确认）。可在 5090 上执行：

```bash
# 训练启动后，另开终端监控（示例：首 epoch val loss 超阈值即杀）
tail -f log.txt | awk '/Vali Loss/{ if ($NF+0 > 2.0) { print "DIVERGED"; exit 1 } }'
```
